# Stops That Need A Person Go To The Issue As `needs-shin`

- `loop/needs_person.go`: `stopForPerson` runs the backlog adapter's optional `stop` action (arg = order id, stdin = what is needed). The GitHub script (`defaults/adapters/github/backlog-stop`) comments once, then removes `ready` and adds `needs-shin` in one edit (Shin, 2026-11-09); the factory reads only `ready`, so a person adding `ready` back is what resumes it. Idempotency keys on `needs-shin` already being up. A backlog with no `stop` script is skipped (`isMissingAdapter`).
- Triggers, each with its own comment text and a test asserting it: a `stage_fail` starting `Unbuildable:` (no Done when), the second agent-reported `stage_fail` for one order ("Two fix rounds failed"), a merge conflict, the spend cap, a stuck PR wait, and a push, ship or merge failure (`stopAfterShipFailure`: "Shipping failed… Failure: <error>", #131). A ship failure used to fail the stage with no stop, so the next rejection's generic text blamed the Done when.
- Failed rounds count in `.noodle/failed-rounds.json`, not on the order: a retry is a fresh order with the same ID. Cleared on stop and on the order's `done`.
- Idempotent: the script does nothing when the label is already up, so a rerun never comments twice.
- Mode: `resolveRunMode` (`loop/shinstack_mode.go`) reads `shinstack-mode:` from the project's CLAUDE.md and overrides `.noodle.toml` `mode`; undeclared or unknown values fall back to the config.
- Test trap: `exec.Command("gh")` resolves from the test process's PATH, not `cmd.Env`. A test that built its own env once ran the real gh; call the stub by absolute path.
- `status --json` `needs_shin` merges `.noodle/needs-shin.json` (loop-recorded stops) with the backlog `stopped` action (`backlog-stopped`: open issues labelled `needs-shin`). A scheduler refusal runs the stop script via the skill, bypassing the loop's record, so the file alone missed it (#87).
- `processControlCommands` stamps `status.json` before writing the ack; the stamp used to land later in the cycle, so `status` read one control behind.
