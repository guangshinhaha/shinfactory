# Review gate (PR landing mode)

- **Shape:** `execute -> quality -> verify (tier high) -> ship`. Ship is the last stage completing (see [[codebase/pr-landing-mode]]), so in PR mode nothing merges earlier. Code: `loop/review_gate.go`, called from `handleCompletion` before `completeWithPR`.
- **Tier** lives on `orderx.Order.Tier` (scheduler wire field `tier`; empty = medium). `none` skips the gate, `low`/`medium` need a `quality` stage after the last `execute`, `high` also needs `verify` after `quality`. A bad shape fails the order at its first stage completion.
- **Files**, per fix round, under `.noodle/gate/<order>/round-N/`: `review.md` (needs a `Covered:` line and a `Findings:` line; listed findings under `Findings: none` still count) and `verify.json` (`head_sha`, `verdict`, `evidence`; `head_sha` must equal the worktree head, re-checked when a later final stage ships). Missing or empty files fail the stage: not run.
- **Verdict comment:** on a verify stage completing (PASS, PASS+NOTES or FAIL) the loop posts the verifier's `verify.json` bytes unchanged, in a json fence, as a PR comment via `Lander.PostVerdict`, before any merge. gantry's `verdict-check` reads it. The loop never writes a verdict of its own. `verdict-posted` in the round dir makes a rerun skip a repeat comment; a failed post fails the stage.
- **Rounds:** a rejection (review findings, verify FAIL, or a quality/verify `stage_fail` in PR mode, via `rejectStage`) reopens stages `lastExecute..current` as pending in canonical state and `orders.json`, `Order.Round++`, same worktree and branch. The findings text goes to the rework execute as a retry note. `maxFixRounds = 1`: the second rejection fails the order, writes `action_needed`, and the stop comment quotes both rejections (each round's reason is kept in `round-N/rejection.txt`). Unbuildable never reworks. The rework launch counts as one attempt in the new round ([[codebase/order-spend-cap]]).
- **Local mode is not gated.** It merges per stage by design (the no-remote fallback). The gate only guards PR mode.
- Tests: `loop/review_gate_test.go` (fakeLander, plus one run through the real `ghLander` with the stub gh). Landing-mechanics tests set `Tier = "none"` so they stay about landing.
- **Missing verdict at ship (#186):** when ship finds `verdict-check` red and no comment carries a verdict for the PR head (`prState.verdictMissing`, surfaced as `pendingError.noVerdict`), `rerunVerifyForMissingVerdict` reopens verify (and later stages) once per head, clears `verdict-posted`, and the rerun posts the verdict, then ships. `verify-rerun` in the round dir holds the head already rerun; a second miss at that head falls back to the red-check wait and stop. A FAIL from the rerun goes through `sendBack`. A red check with a verdict at the head is the stale-check case (#129) and still just waits.
