# Merge conflict at ship: rebase once, then stop

- **Trigger:** `ghLander.MarkReadyAndMerge` returns `ErrPRConflict` when `gh pr view` shows `mergeable: CONFLICTING` or `mergeStateStatus: DIRTY`. Handler: `onShipConflict` in `loop/rebase.go`, called from `completeWithPR` and `shipParkedPR` (so approve and the checks retry both reach it).
- **First conflict:** `Lander.RebaseOntoBase` fetches the base, rebases, force-pushes with a lease. Stages from the first `quality` after the last `execute` up to the shipping stage reopen as pending (`reopenStages`, same round), so review and verify run on the new head. A tier with no review stage ships the rebased head straight away.
- **Stop:** a rebase that conflicts (rebase aborted, branch untouched), or a second conflict after one rebase, calls `stopConflicted`: `action_needed` line, `merge.conflict` event with `Files`, `stopForPerson` (needs-shin), stage failed. Second-conflict files come from `Lander.ConflictingFiles` (`git merge-tree`). Nothing retries a stopped order.
- **Count:** `.noodle/rebased.json` per order id, written atomically (`filex.WriteFileAtomic`). Cleared on stop, on done, on any `failStage` and on skip, so a retry under the same id gets its rebase. It is per order, not per base: a much later conflict still stops (decided, keeps "once" bounded). `stopConflicted` always runs the stop and the clear, even if `flagActionNeeded` fails.
- **Parked path:** the `PendingReviews` entry is restored if `reopenStages` fails.
- **UNKNOWN mergeability:** `checksPending` treats `mergeable: UNKNOWN` as pending, so a fresh push waits instead of reaching `gh pr merge`.
- **Shared files:** a stage lists `extra.writes: ["brain/index.md"]`; `withoutWriteClashes` (`loop/shared_writes.go`) holds back a candidate whose file a running stage or an earlier candidate in the batch holds. Holders are running, adopted (order's active stage) and pending-review stages. Paths overlap case-insensitively and by directory prefix (`writePathsOverlap`).
- Fixture: `loop/rebase_gh_test.go` (real git, stub gh with `STUB_MERGEABLE_BY_GIT` to model a repo that needs up-to-date branches). Real GitHub reports a plain textual overlap as CONFLICTING, which a rebase also hits, so in practice the rebase clears stale or already-landed overlaps and the stop path handles the rest.
