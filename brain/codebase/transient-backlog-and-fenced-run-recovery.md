# Transient Backlog Errors Retry; A Fenced Orca Run Is Replaced

- A network-class error (`isNetworkError`: `net.Error`, errno, or text markers for DNS, refused/reset, timeouts, `can't assign requested address`, GitHub 5xx) in `Cycle`'s backlog sync (`buildBriefWithRetry`) or worktree creation (spawn) never ends `start`. `recordNetworkFailure` opens `Loop.outage` (one warn per outage), backs off 1s doubling to 5 min, and `stateLabel` (status file, snapshot, `NormalizeLoopState`) shows `loop=waiting-network`. The cycle returns instead of sleeping, so control commands keep running; `buildBriefWithRetry` is the gate while backoff runs. Maintenance errors are not caught (completions are consumed before they fail); parked-PR merge retries already treat `isNetworkError` as transient in `landing.go`. `clearNetworkOutage` runs when a cycle gets through spawn. There is no retry window any more (`[backlog] retry_window_seconds` was removed). Other errors (401, 404, not a git repo) stay fatal. Seams: `Dependencies.Now`, `fakeWorktree.createErrFn`.
- `OrcaDispatcher.Dispatch` replaces the run once on `consumer_fenced` (host sleep): `replaceRun` creates and records a new run, then retries worker-start. A second fence surfaces.
- Fixtures: `loop/backlog_retry_test.go`, `loop/network_wait_test.go`, `fakeorca.FenceConsumer`.
