# Transient Backlog Errors Retry; A Fenced Orca Run Is Replaced

- A network-class error (`isNetworkError`: `net.Error`, errno, or text markers for DNS, refused/reset, timeouts, `can't assign requested address`, GitHub 5xx) in `Cycle`'s backlog sync (`buildBriefWithRetry`) or worktree creation (spawn) never ends `start`. `recordNetworkFailure` opens `Loop.outage` (one warn per outage), backs off 1s doubling to 5 min, and `stateLabel` (status file, snapshot, `NormalizeLoopState`) shows `loop=waiting-network`. The cycle returns instead of sleeping, so control commands keep running; `buildBriefWithRetry` is the gate while backoff runs. Maintenance errors are not caught (completions are consumed before they fail). Instead, a network error in a post-cook PR call (push/draft PR, ship, verdict post, rebase fetch) goes through `failStageOrWaitNetwork`: the stage parks with reason prefix `waiting for the network` (order, worktree, session kept) and `retryNetworkParked` re-runs `completeAfterEvidence` once the backoff passes (all those steps are idempotent; the rebase count is taken back). Parked-PR merge retries record the outage instead of warning every poll. `clearNetworkOutage` waits while any stage is network-parked. `unexpected eof` is not a marker: a truncated local file would wait forever. `clearNetworkOutage` runs when a cycle gets through spawn. There is no retry window any more (`[backlog] retry_window_seconds` was removed). Other errors (401, 404, not a git repo) stay fatal. Seams: `Dependencies.Now`, `fakeWorktree.createErrFn`.
- `OrcaDispatcher.Dispatch` replaces the run once on `consumer_fenced` (host sleep): `replaceRun` creates and records a new run, then retries worker-start. A second fence surfaces.
