# 146 — Dashboard Ready page (Inbox count, reorder, slots, mode)

## Context

Issue #146, part of the dashboard redesign (#138). Today the dashboard has no view of what the line picks up next. Reorder, slot and mode controls exist as control actions (`reorder`, `set-max-concurrency`, `mode` in `ui/src/client/types.ts`, handled in `loop/control.go` and `loop/control_orders.go`) but only the CLI uses them. "Talk to the scheduler" is the steer composer inside `SchedulerFeed`, and a stub "New Order" button sits in `Dashboard.tsx`.

Findings that shape the plan:

- The snapshot (`internal/snapshot/types.go`) has `orders`, `mode` and `max_concurrency`, but no ready issues, no inbox count, and no tier on orders. Ready-but-unplanned issues only exist in the mise brief (`Brief.Backlog`, from `backlog-sync`).
- `defaults/adapters/github/backlog-sync` returns ready issues only, so the Inbox count needs a new source. The scheduler must never see inbox items (see [[codebase/orders-must-name-a-ready-issue]]).
- `reorder` takes an index into the whole `orders.json` array, which includes active orders. The UI cannot use an index within the Ready list.
- Ready issues with no order yet cannot be reordered: no order id exists until the scheduler plans them (see issue #217).
- The `/scheduler` route does not exist yet. #143 moves the feed there. The scheduler feed lives at `/` today.

## Scope

In: `/ready` route and nav entry; Ready list (queued orders first, then unplanned ready issues) with planned stages and tier; Inbox count (read only); move up/down via `reorder`; slots stepper via `set-max-concurrency`; mode toggle via `mode`; "label an issue `ready`" copy; collapsed "Emergency: steer the scheduler" drawer (with the Open in Orca line on orca); remove `/scheduler` and the stub New Order button.

Out: Running, Needs Shin, Shipped pages (#143, #145, #147); top bar (#153); removing Topology and Onboarding (#148); making unplanned issues reorderable (needs scheduler change, file separately); inbox triage actions (count only).

## Dependencies

- #143 lands first (Running at `/`, feed moved to `/scheduler`). This plan deletes `/scheduler`. If #143 has not landed when phase 7 starts, phase 7 deletes the scheduler channel from `/` instead, and the implementer says so in the PR.
- #153 (top bar) touches the root layout and nav. Rebase over it; do not duplicate its controls.
- Nav order is fixed by Shin's vocabulary: Running, Needs Shin, Ready, Shipped. Only add Ready; do not rename the other items here.

## Constraints and alternatives

Inbox count source:
1. Emit unlabelled issues from `backlog-sync` with a status. Rejected: leaks into `Brief.Backlog` and the scheduler.
2. New optional adapter action `backlog-inbox` that prints a count. Chosen: scheduler never sees it, one clear failure mode, and the same gh call pattern as sync.
3. Dashboard server calls `gh` directly. Rejected: bypasses the adapter boundary and breaks non-GitHub backlogs.

Ready ordering in the snapshot:
1. UI derives rows from `orders` + a raw backlog list. Rejected: duplicates scheduler/pick-up logic in TS.
2. Snapshot builds one ordered `ready` list (order rows, then unplanned issues). Chosen: one place defines pick-up order, UI stays a view. Each row carries its `orders.json` index so reorder needs no mapping in the UI.

Mode and slots are plain controls over existing actions; no new server code. No backward compatibility shims (project rule).

## Principles

- **model-the-domain**: name the Ready row shape and the inbox count before logic; one list defines pick-up order.
- **sequence-verifiable-units**: each phase ends with a runnable check; backend data before UI.
- **laziness-protocol**: reuse existing control actions, `useSendControl`, `OrcaSteerNotice`; no new control verbs.
- **boundary-discipline**: the adapter returns a validated count; the UI trusts snapshot types generated by tygo.
- **migrate-callers-then-delete-legacy-apis**: move the steer composer, then delete `/scheduler` and the New Order button last.
- **prove-it-works**: every phase names its command.
